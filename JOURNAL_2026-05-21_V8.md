## Le bug racine : data leakage PDH/PDL

### Découverte

Dans `ml_filter.py:_features_from_result` et `ml_dataset.py:_get_daily_levels`,
le code filtrait sur `df_d1.index < ts` au lieu de `df_d1.index < ts.normalize()`.

Conséquence :
- **Training** : la D1 du jour de validation était COMPLÈTE dans le parquet → utilisée comme "yesterday" → features incluant le futur
- **Live** : la D1 du jour est PARTIELLE → "yesterday" était la D1 d'hier (correct)
- → Le ML voyait deux distributions de features différentes → probas écrasées en live

### Fix V8

```python
# AVANT (bug)
past = df_d1[df_d1.index < ts]

# APRES (V8)
past = df_d1[df_d1.index < ts.normalize()]
```

Impact mesuré : 60 setups testés, écart jusqu'à ±0.43 de proba ML entre training et live.

## Tous les bugs corrigés aujourd'hui

Le 0 trade venait d'une **pile de 9 problèmes** :

### 1. Data leakage PDH/PDL (V8 fix)
→ rebuild complet, voir ci-dessus.

### 2. `max_group_size` divergent (OOS misalignment)
- OOS : `detect_order_blocks(...)` → défaut **5**
- Live : `detect_order_blocks(..., max_group_size=2)` → **2**
- → Live détectait MOINS d'OB que le training
- **Fix** : retiré `max_group_size=2` partout (live + 5 scripts diag)

### 3. Évaluation multiple d'un OB (OOS misalignment)
- OOS : évalue chaque OB **1 seule fois** à validation
- Live : ré-évaluait l'OB à chaque cycle pendant `recent_cutoff`
- → Un OB rejeté à validation+1min pouvait être repris 30min plus tard
- **Fix** : `state._evaluated_obs` marque tout OB évalué → plus jamais ré-évalué

### 4. `recent_cutoff` 3min (trop court)
- 3min → bot ne voyait qu'1 OB ultra-frais par cycle
- Un OB qui mûrit (retest → proba monte à 0.75) sortait de la fenêtre
- **Fix** : 3min → 60min (avec `_evaluated_obs` qui dédoublonne)

### 5. `BOT_START_TS` -1min (post-redémarrage)
- Au redémarrage, le bot ignorait tous les OB validés avant le boot
- SETUP détecté ML 0.759 → "SKIP pre-start"
- **Fix** : -1min → -60min (cohérent avec `recent_cutoff`)

### 6. `age_setup_min` 3min (SETUP TROP VIEUX)
- 3ème filtre d'âge qui rejetait après calcul des lots
- SETUP UK100 ML 0.711 → "TROP VIEUX 23.7 min, SKIP"
- **Fix** : 3min → 60min (aligné `recent_cutoff`)

### 7. OOM VPS Contabo (RAM saturée)
- Parquets V8 = 8 ans (2.7M+ bougies M1/actif)
- DataBuffer chargeait 17 actifs × 8 ans en RAM → ~4 GB
- VPS 8 GB → OOM → bot tué silencieusement
- **Fix** : `MAX_BUFFER_BARS = 130k` (~4.5 mois) → RAM 90 MB total

### 8. AutoTrading MT5 désactivé
- `retcode=10027 : AutoTrading disabled by client`
- Bouton "Trading Algo" rouge → MT5 refusait TOUS les ordres
- **Fix** : bouton activé → vert ✅

### 9. Calcul de marge erroné
- Code utilisait `info.margin_initial * lots`
- Pour Forex, `margin_initial` = taille contrat (100000), pas la marge
- USDCAD 0.15 lot → "marge requise 15000€" → rejet à tort
- **Fix** : `mt5.order_calc_margin(BUY/SELL, ...)` → vraie marge (USDCAD 0.15 lot = 25.89€)

## Leçons retenues

1. **Le code peut être parfait, ça ne marche pas si une checkbox MT5 est désactivée.** Toujours vérifier les pré-requis externes (AutoTrading) AVANT de chercher des bugs dans le code.

2. **Aligner live ↔ training est CRUCIAL.** Un seul paramètre différent (`max_group_size`) crée un univers d'OB différent → modèle inutilisable. Audit systématique de chaque appel.

3. **Les filtres d'âge accumulés sont un piège.** 3 filtres différents (cutoff, BOT_START_TS, age_setup) avec des durées incohérentes → bot bloqué. Toujours **un seul** filtre canonique d'âge, le reste s'aligne dessus.

4. **MT5 `info.margin_initial` n'est PAS la marge.** Utiliser `order_calc_margin()` qui tient compte du levier.

5. **Le ML est honnête sur sa calibration.** Si l'OOS dit "WR 77% @ 0.70" et est mesuré sur 6276 trades réels, c'est fiable. Le live divergence vient toujours d'un misalignment training/live (pas du modèle).

6. **Le data leakage est subtil et invisible en backtest.** `df.index < ts` vs `df.index < ts.normalize()` paraît identique. Une seule lettre fait passer "yesterday = D1 du jour complet" à "yesterday = vraie D1 d'hier". Vérifier toute condition temporelle avec `.normalize()` quand on travaille sur des barres journalières.
